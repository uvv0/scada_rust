# Секция: `im1`

Работаем в проекте: `C:\andr\my2\im1`.

## Что это
- Rust-приложение: UDP-имитатор + GUI (`eframe/egui`).
- UDP bind: `127.0.0.1:5100`.
- Обработка Modbus-подобных команд в `src/imm.rs` (`raz2`).

## Важные правила данных
- Используются два раздельных массива:
  - `DAT` -> `input` (FC04 + левая колонка GUI).
  - `DAT1` -> `holding` (FC03/FC16 + правая колонка GUI).
- Пересечения между `input` и `holding` быть не должно.

## Адреса/диапазоны
- Input floats (GUI слева): 12 `f32` с `0x20` (по 2 регистра на float).
- Holding floats (GUI справа): 24 `f32` с `0x10` (по 2 регистра на float).

## Формат `f32`
- Порядок байтов принят как `BE`:
  - пример: `16.300` -> `41 82 66 66` (IEEE754 `f32`).
- Для записи/чтения используются:
  - `wr_float` / `rd_float` -> `DAT`.
  - `wr_float_holding` / `rd_float_holding` -> `DAT1`.

## UI
- Слева: редактирование input (12 значений).
- Справа: редактирование holding (24 значения).
- Поля автообновляются из массива, если поле не в фокусе.
- Тема/цвета приведены к стилю `ss5`.

## Что проверять после изменений
1. `cargo check`
2. `cargo build --release`
3. Ручная проверка:
   - запись FC16 в holding меняет `DAT1` и видно на правой панели;
   - чтение FC03 берет данные из `DAT1`;
   - чтение FC04 берет данные из `DAT`;
   - input/holding не влияют друг на друга.
