# SCADA-компоненты на базе регистров

## Назначение

SCADA-компонент в `ss7` это способ отобразить одну привязку регистра в окне KPZ.
Одна привязка хранит:

- источник данных: `reg_id`
- геометрию: `x`, `y`, `w`, `h`
- режим отображения: `component_kind`
- подпись и формат: `label_override`, `unit`, `fmt`
- поведение: `visible`, `writable`

Компонент не меняет источник данных. Он меняет только то, как значение выглядит в preview и как с ним можно взаимодействовать.

---

## Где это хранится

- Модель: `src/models.rs`, структура `UiWindowBindingRow`
- БД окна: `ui.kpz_window_reg_binding`
- БД шаблона окна: `ui.kpz_window_template_binding`
- Миграции: `src/db_schema.rs`
- Загрузка/сохранение: `src/db.rs`
- Редактор и preview: `src/ui/window_link_editor.rs`

Поле компонента:

```rust
pub component_kind: Option<String>
```

Значения:

- `None` или `"auto"`
- `"led"`
- `"numeric"`
- `"bar"`
- `"gauge"`
- `"setpoint"`
- `"button"`
- `"trend"`; мини-график истории значений в preview

## Что реализовано сейчас

На текущий момент в проекте реализовано следующее:

- выбор `component_kind` в редакторе Bindings
- сохранение и загрузка `component_kind` в БД
- отображение в preview для:
  - `auto`
  - `led`
  - `numeric`
  - `bar`
  - `gauge`
  - `setpoint`
  - `button`
- `trend` с отдельной отрисовкой мини-графика в preview

Важно:

- `auto` продолжает опираться на тип регистра `reg_tip`
- `button`, `setpoint`, `writable` влияют не только на внешний вид, но и на интерактивность
- цвет аларма берётся из правил `alarm_rule`, если они загружены для регистра

---

## Логика выбора компонента

### `auto`

Режим по умолчанию. Тип виджета определяется автоматически по данным регистра:

- текстовая привязка: статическая надпись
- `reg_tip == 0` и есть `reg_bits`: битовый индикатор
- `reg_tip == 1` или `reg_n_mb == 1`: ТУ-компонент `OFF | ON`
- остальные числовые регистры: числовой блок

`auto` нужен для обратной совместимости со старыми окнами и шаблонами.

## Как выглядит каждый компонент

### `led`

Назначение:

- для битовых сигналов
- отображает состояние `0/1`

Как выглядит:

- тёмный прямоугольный фон области компонента
- внутри круглый индикатор
- если значение `>= 0.5`, индикатор светится
- если значение `< 0.5`, индикатор тёмный
- снизу текст `ON` или `OFF`

Цвет:

- без алармов: зелёный при `ON`
- с алармами:
  - красный: авария
  - жёлтый: предавария
  - зелёный: норма

Когда использовать:

- дискретный вход
- состояние реле
- флаг работы
- битовая сигнализация

Пример визуально:

- `OFF`: тёмный круг в белой рамке
- `ON`: яркий круг и подпись `ON`

### `numeric`

Назначение:

- показать числовое значение без редактирования

Как выглядит:

- прямоугольный блок с ровным тёмно-синим фоном
- в центре крупное число
- подпись регистра выводится слева от блока

Особенности:

- это read-only визуализация
- если данных нет, показывается `-`

Когда использовать:

- давление
- температура
- ток
- напряжение
- счётчики

### `bar`

Назначение:

- показать уровень по шкале от 0 до 100

Как выглядит:

- тёмный прямоугольный трек
- внутри заливка слева направо
- по центру текущее значение

Цвет:

- без алармов: синий
- с алармами:
  - красный
  - жёлтый
  - зелёный

Текущая реализация:

- шкала пока фиксирована `0..100`
- вертикальный bar пока не реализован

Когда использовать:

- уровень
- загрузка
- процент открытия
- позиция

### `gauge`

Назначение:

- показать значение как стрелочный индикатор

Как выглядит:

- тёмный прямоугольный фон
- полуокружность-шкала
- стрелка от левого края к правому
- в нижней части текстовое значение в процентах

Текущая реализация:

- шкала нормализована в диапазон `0..100`
- стрелка меняет положение по значению
- цвет стрелки учитывает alarm level

Когда использовать:

- давление
- температура
- расход
- обороты

### `setpoint`

Назначение:

- показать число как уставку или задаваемый параметр

Как выглядит:

- прямоугольный блок
- слева цветовой акцент
- сверху/по центру текущее значение
- снизу маленькая подпись:
  - `setpoint`, если запись разрешена
  - `readonly`, если запись запрещена

Поведение:

- если `writable == true`, компонент можно редактировать в preview
- при клике включается режим ввода
- запись идёт по Enter

Когда использовать:

- уставка температуры
- уставка давления
- порог включения
- задание частоты

### `button`

Назначение:

- отобразить командный элемент

Как выглядит:

- выделенный прямоугольный блок с более "кнопочным" фоном
- сверху лёгкий светлый блик
- в центре надпись:
  - `WRITE`, если запись разрешена
  - `BUTTON`, если только визуальный режим

Поведение:

- если `writable == true`, клик по preview отправляет запись `1.0`
- это базовый вариант командной кнопки

Когда использовать:

- пуск
- стоп
- квитирование
- тестовая команда

Ограничение:

- текущая версия не поддерживает сценарии типа "нажать, подождать, сбросить"
- если нужна такая логика, её надо расширять отдельно

### `auto`

Назначение:

- оставить старое поведение без ручного выбора компонента

Как выглядит:

- для битов: старый битовый блок
- для ТУ: две зоны `OFF | ON`
- для чисел: стандартный прямоугольник со значением

Когда использовать:

- если не нужен явный SCADA-виджет
- для старых окон без донастройки

### `trend`

Назначение:

- мини-график изменения значения во времени

Состояние:

- тип предусмотрен в модели и документации
- в preview рисуется линия по накопленной истории значений
- история собирается по `reg_id`
- текущая реализация хранит до 48 последних значений

Как должен выглядеть в будущем:

- прямоугольная область
- линия по последним N значениям
- подпись текущего значения
- возможно, маркеры min/max

---

## Как компоненты связаны с типом регистра

`component_kind` не отменяет тип регистра, а работает поверх него.

Примеры:

- битовый регистр можно показать как `led`
- обычный числовой регистр можно показать как `numeric`, `bar`, `gauge`, `setpoint`
- writable-регистр можно показать как `setpoint` или `button`
- ТУ-регистр в `auto` останется двухзонным `OFF | ON`

Если выбран явно неподходящий тип, система всё равно пытается его нарисовать по имеющемуся числу. Поэтому корректный выбор компонента остаётся задачей редактора окна.

---

## Влияние alarm-уровней

Для части компонентов цвет зависит от alarm-уровня:

- `led`
- `bar`
- `gauge`
- стандартные `auto`-числовые блоки

Правила:

- `HI` или `LO`: красный
- `HI_1` или `LO_1`: жёлтый
- без срабатывания: зелёный

Если alarm rules не загружены, используется базовый цвет компонента.

---

## Взаимодействие в preview

### Левый клик

- `button` и writable-регистр: команда записи
- `setpoint` и writable numeric: переход в режим ввода
- `TU`: выбор левой/правой зоны `OFF | ON`
- bit writable: переключение `0/1`

### Правый клик

- для 16-битных holding-регистров открывается редактор битов
- для остальных может показываться информация по alarm-порогам

## Практические рекомендации

### Для дискретных сигналов

Использовать:

- `led`

Не использовать:

- `numeric`, если нужен быстрый визуальный контроль

### Для аналоговых значений

Использовать:

- `numeric`, если важна точность
- `bar`, если важен уровень
- `gauge`, если нужен операторский приборный вид

### Для задаваемых параметров

Использовать:

- `setpoint`

### Для команд

Использовать:

- `button`
- либо `auto`, если это именно ТУ-логика `OFF | ON`

---

## Ограничения текущей реализации

- `bar` и `gauge` пока работают как шкала `0..100`
- нет пользовательских `scale_lo` / `scale_hi`
- нет отдельного свечения, теней и сложной анимации
- `trend` реализован как preview-компонент без отдельной настройки шкалы/оси времени
- `button` пока пишет фиксированное значение `1.0`
- нет отдельного runtime-слоя командных сценариев для SCADA-кнопок
