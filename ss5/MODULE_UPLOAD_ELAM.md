# Загрузка модуля в W25Q128 через ELAM Modbus

Этот способ передаёт файл `module_slotN.bin` через UART8 в RAM-буфер основной
прошивки, проверяет его и только после отдельного подтверждения записывает в
выбранный слот W25Q128. J-Link, ST-Link и `.stldr` при этом не используются.

## Условия

- основная прошивка уже записана во внутреннюю Flash и запущена;
- UART8 работает как `19200 8N1`;
- адрес ELAM — `301`;
- инициализирован поток `mod_upload`;
- для записи передаётся готовый файл `module_slotN.bin`, включая
  10-байтный заголовок;
- допустимая длина файла — `10..4096` байт;
- допустимый номер слота — `0..19`.

Формат расширенного адреса ELAM для станции 301:

```text
F8 35
```

После этих двух байтов располагаются код функции и стандартные поля Modbus.
CRC16 Modbus вычисляется по всему кадру, начиная с `F8 35`, и передаётся
младшим байтом вперёд.

## Карта регистров

Окно доступно функцией `03` для чтения и функциями `06/16` для записи.

| Holding | Доступ | Назначение |
|---:|---|---|
| `10000..12047` | R/W | 4096-байтный RAM-буфер, 2048 слов |
| `12048` | R/W | номер слота `0..19` |
| `12049` | R/W | фактическая длина файла `10..4096` |
| `12050` | W | команда |
| `12051` | R | состояние операции |
| `12052` | R | результат `MODULE_*` |
| `12053` | R | вычисленный CRC16 модуля |
| `12054` | R | одноразовый token после проверки |
| `12055` | R/W | подтверждение token перед записью |

Команды для регистра `12050`:

| Значение | Команда |
|---:|---|
| `0xA501` | проверить RAM-буфер |
| `0xA502` | записать проверенный буфер в W25Q128 |
| `0xA503` | запустить выбранный слот |
| `0xA504` | остановить выбранный слот |

Состояния регистра `12051`:

| Значение | Состояние |
|---:|---|
| `0` | ожидание или данные изменены после проверки |
| `1` | выполняется проверка |
| `2` | буфер успешно проверен |
| `3` | выполняется запись |
| `4` | слот успешно записан |
| `5` | ошибка |
| `6` | модуль запускается |
| `7` | модуль работает |
| `8` | модуль останавливается |
| `9` | модуль остановлен |

Результат также публикуется для чтения функцией `04`:

```text
TIT[2450]  состояние
TIT[2451]  результат MODULE_*
TIT[2452]  вычисленный CRC16
TIT[2453]  выбранный слот
TIT[2454]  длина файла
```

Для token необходимо использовать функцию `03` и Holding `12054`.

## Преобразование файла в Holding-регистры

Два последовательных байта файла образуют одно 16-битное слово:

```text
word = (file[offset] << 8) | file[offset + 1]
Holding = 10000 + offset / 2
```

То есть старший байт слова передаётся первым. Начало текущего
`module_slot0.bin`:

```text
Файл:    B5 66 0C 00 00 00 01 00 01 00 00 00 2D E9 ...
Holding: 10000=B566
         10001=0C00
         10002=0000
         10003=0100
         10004=0100
         10005=0000
         10006=2DE9
```

Если длина файла нечётная, младший байт последнего слова следует заполнить
`FF`, а в `12049` всё равно записать точную нечётную длину.

Изменение любого слова буфера, номера слота или длины немедленно отменяет
предыдущую проверку и обнуляет token. После такого изменения шаг проверки
нужно выполнить заново.

## Разбиение на запросы

Один запрос Modbus function `16` содержит не более 123 регистров, то есть
246 байт файла. Адрес следующего блока увеличивается на фактически переданное
число регистров.

Для полного файла 4096 байт требуется:

```text
16 блоков по 123 слова = 3936 байт
1 блок на 80 слов      =  160 байт
Итого                  = 4096 байт, 17 запросов
```

Входной пакет `raz2()` ограничен 1200 байтами. Не следует объединять все
17 запросов в один GPRS-пакет. Безопасно передавать не более четырёх полных
запросов FC16 по 123 слова за один пакет и ждать ответы перед следующей
группой.

Общий формат одного запроса FC16:

```text
F8 35 10 AH AL QH QL BC [данные] CRClo CRChi
```

где:

- `AH AL` — начальный Holding-адрес;
- `QH QL` — количество слов;
- `BC` — количество байтов данных, `quantity * 2`;
- данные идут старшим байтом каждого слова вперёд.

Нормальный ответ:

```text
F8 35 10 AH AL QH QL CRClo CRChi
```

Ответ с кодом функции `0x90` является Modbus Exception. Код `04` обычно
означает, что загрузчик занят другой длительной операцией.

## Полная безопасная последовательность

### 1. Передать файл

Передать все слова файла последовательными запросами FC16, начиная с
Holding `10000`. После каждого запроса проверить нормальный ответ.

Для дополнительного контроля можно прочитать переданные блоки обратно
функцией `03` и побайтно сравнить с исходным файлом.

### 2. Задать слот и длину

Записать:

```text
Holding[12048] = номер слота
Holding[12049] = точная длина файла в байтах
```

Их можно передать одним запросом FC16 на два слова.

### 3. Запустить проверку

Записать функцией `06`:

```text
Holding[12050] = 0xA501
```

Команда ставится в очередь, поэтому нормальный ответ FC06 означает только
приём команды, а не завершение проверки.

Опросить функцией `03` регистры `12051..12054`, пока:

```text
12051 = 2
12052 = 0
12053 = вычисленный CRC16
12054 = ненулевой token
```

При `12051 = 5` операция завершилась ошибкой; причина находится в `12052`.

Token вычисляется прошивкой:

```text
token = crc XOR (slot << 8) XOR length XOR 0x5AA5
```

Если результат равен нулю, используется `0xA55A`. Клиенту не требуется
вычислять token самостоятельно — надёжнее прочитать `12054`.

### 4. Подтвердить запись

Скопировать прочитанное значение без изменений:

```text
Holding[12055] = Holding[12054]
```

Не менять после этого буфер, слот или длину: любое изменение аннулирует
подтверждение.

### 5. Записать W25Q128

Записать функцией `06`:

```text
Holding[12050] = 0xA502
```

Опросить `12051..12053`, пока:

```text
12051 = 4
12052 = 0
12053 = CRC16 проверенного модуля
```

Во время записи поток загрузчика при необходимости останавливает уже
работающий модуль выбранного слота и блокирует конфликтующие операции
FlashDB. После простой записи модуль остаётся остановленным.

### 6. Запустить модуль при необходимости

Записать:

```text
Holding[12048] = номер слота
Holding[12050] = 0xA503
```

Дождаться:

```text
12051 = 7
12052 = 0
```

Для остановки используется команда `0xA504`; успешное состояние — `9`.

## Коды результата

Регистр `12052` имеет тип `u16`, поэтому отрицательные значения читаются в
дополнительном коде.

| Код C | Значение Modbus | Причина |
|---|---:|---|
| `MODULE_OK` | `0x0000` | успешно |
| `MODULE_ERR_SLOT` | `0xFFFF` | неверный слот |
| `MODULE_ERR_HEADER` | `0xFFFE` | неверный заголовок или команда |
| `MODULE_ERR_SIZE` | `0xFFFD` | неверная длина |
| `MODULE_ERR_CRC` | `0xFFFC` | CRC не совпал или неверный token |
| `MODULE_ERR_VERSION` | `0xFFFB` | запрещённая версия |
| `MODULE_ERR_FLASH` | `0xFFFA` | ошибка W25Q128 |
| `MODULE_ERR_RAM` | `0xFFF9` | зарезервировано |
| `MODULE_ERR_THREAD` | `0xFFF8` | поток модуля не создан |
| `MODULE_ERR_BUSY` | `0xFFF7` | операция или слот заняты |

После ошибки исправить причину и начать снова с проверки. Если менялись
данные, слот или длина, старый token использовать нельзя.

## Контрольный алгоритм клиента

```text
прочитать module_slotN.bin
проверить длину 10..4096
разбить байты на 16-битные слова big-endian
передать слова блоками <= 123 через FC16 с адреса 10000
записать slot -> 12048
записать length -> 12049
записать A501 -> 12050
ждать status=2 и result=0
прочитать token <- 12054
записать token -> 12055
записать A502 -> 12050
ждать status=4 и result=0
при необходимости записать A503 -> 12050
ждать status=7 и result=0
```
