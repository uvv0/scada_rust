# Универсальный загрузчик OBJ1

Приложение `h750.exe` содержит одну вкладку `OBJ1` вместо отдельных
загрузчиков module-slot и WEB1.

Старые `module_programming.*`, `web_programming.*` и обе старые вкладки
полностью удалены из проекта; OBJ1 самостоятельно формирует и проверяет
Modbus RTU-кадры.

Поддерживаются:

- XIP module;
- Web file;
- Lua VM;
- Lua script;
- bytecode;
- device profile;
- configuration;
- tag dictionary.

## Подготовка объекта

1. Выбрать тип OBJ1.
2. Указать `object_id`.
3. Открыть payload-файл.
4. Проверить имя объекта. Для Web это URL, начинающийся с `/`.
5. Для Web выбрать content type.
6. Для XIP module и Lua VM указать:
   - требуемую версию API;
   - link address payload;
   - entry offset относительно начала payload;
   - AUTOSTART при необходимости.
7. Нажать `Записать OBJ1`.

Qt формирует 128-байтный заголовок `OBJ1`, добавляет payload и вычисляет:

- CRC32 payload;
- CRC32 первых 124 байт заголовка;
- CRC32 полного передаваемого образа.

Поля заголовка записываются little-endian. Имя занимает не более 39 байт
UTF-8 плюс завершающий ноль.

Для XIP `link_address` является CPU-адресом начала payload:

```text
0x90000000 + first_block × 4096 + 128
```

Поэтому допустимые адреса имеют младшие 12 бит `0x080`. Контроллер обязан
выделить именно тот `first_block`, который следует из link address.

## Передача

Образ передаётся последовательно блоками до 4096 байт через общий RAM-буфер
Holding `10000..12047`. Один блок разбивается на FC16-запросы максимум по
123 регистра.

Управляющие регистры:

```text
12048..12049  полный размер OBJ1, u32
12050..12051  ожидаемый CRC32 полного OBJ1
12052..12053  смещение текущего блока, u32
12054         размер текущего блока
12055         команда
12056         состояние
12057         результат
12058..12059  записано байт, u32
12060..12061  вычисленный CRC32 полного OBJ1
12062..12063  object_id, u32
12064         назначенный first_block
12065         block_count
12066..12067  generation активного каталога, u32
```

Команды:

```text
0xA521  begin
0xA522  записать текущий блок
0xA523  проверить объект и атомарно переключить каталог
0xA524  отменить загрузку
```

Состояния:

```text
0  idle
1  подготовка/стирание
2  ready
3  writing
4  chunk ok
5  complete
6  error
7  aborted
```

## Требования к контроллеру

На `begin` контроллер проверяет размер и создаёт сессию, но не удаляет старый
объект.

Первый переданный блок содержит заголовок. Контроллер:

1. проверяет magic, версию, тип, размеры и header CRC;
2. вычисляет необходимый `block_count`;
3. для XIP проверяет link address и выбирает заданный им first block;
4. для остальных объектов находит свободный непрерывный диапазон;
5. стирает только новые блоки;
6. записывает блок и читает его обратно.

На `commit` контроллер повторно читает весь объект, проверяет header CRC,
payload CRC и CRC полного образа, записывает неактивный каталог A/B и
программирует CRC каталога последним.

Старые блоки объекта освобождаются только после успешного переключения
каталога.

## Актуальная работа вкладки Lua через COM/UDP

Поле `Lua-слот COM` выбирает один из 32 скриптов. Для слота `N` используются:

- Object ID `0x4C530000 + N`;
- имя `vm_NN.lua`;
- максимальный размер текста 3968 байт;
- общий пул QSPI-блоков 128..159.

Кнопки `Прочитать`, `Записать`, `COM-чтение`, `COM-запись`, `Запустить VM`,
`Остановить VM`, `Статус VM`, `Статус слотов` и `Обновить теги` работают через
общий выбранный транспорт. При установленной галочке `udp` используется UDP
на IP контроллера и порт 5100, иначе COM6. Перед операциями записи, чтения,
запуска и остановки фоновый опрос тегов автоматически прекращается, чтобы
ответы разных операций не пересекались.

### Теги выбранного Lua-слота

После выбора слота кнопка `Обновить теги` выполняет следующую цепочку:

1. читает сохранённый `vm_NN.lua` из OBJ1 контроллера;
2. помещает прочитанный текст в редактор;
3. находит все вызовы `tag.get(port, device, id)` и
   `tag.set(port, device, id, value)`;
4. удаляет повторяющиеся адреса;
5. читает каждый найденный тег непосредственно из `tag_registry`;
6. обновляет значения раз в секунду.

Между последовательными UDP-запросами выдерживается пауза 80 мс. Статус и
значение одного тега занимают четыре регистра в read-only окне `tag_registry`,
начиная с адреса 14000. Таблица тегов показывает только адреса, используемые
выбранным скриптом, а не все теги выбранного устройства.

### Состояние Lua-слотов

Кнопка `Статус слотов` открывает отдельное окно для редко используемой
диагностики всех 32 скриптов. Данные читаются одним FC03-запросом на 100 слов:

```text
32000       версия формата, сейчас 1
32001       количество работающих слотов
32002..3    32-битная маска работающих слотов, high word / low word
32004..99   по три слова на слот: state, result high, result low
```

Состояния слота: `0 = нет`, `1 = работает`, `2 = выполнен`, `3 = ошибка`.
Это состояние отдельных `vm_01.lua..vm_32.lua`; кнопка `Статус VM` отдельно
показывает состояние исполняемого OBJ1-модуля `lua_vm.bin` с Object ID 5.
# Lua через Ethernet

Вкладка `Lua` работает напрямую с HTTP API контроллера. Поле
`Контроллер` принимает IP-адрес или полный адрес с портом; значение по
умолчанию — `192.168.1.100`.

- `Прочитать` — загрузить сохранённый Lua script по Object ID;
- `Записать` — атомарно заменить текст скрипта в OBJ1-каталоге;
- `Запустить VM` — запустить уже сохранённый скрипт;
- `Записать и запустить` — сначала сохранить текущий текст редактора,
  затем запустить Lua VM;
- `Статус VM` — показать состояние и `last_result`;
- `Обновить теги` — прочитать `/api/tags`. Двойной щелчок по тегу
  вставляет в редактор аргументы `порт, устройство, ID`.

Кнопки `COM-запись` и `COM-чтение` записывают и читают текст редактора через
выбранный COM-порт и ELAM 301, не используя Ethernet. Поле `Lua-слот COM`
выбирает слот `1..32`:

- Object ID: `0x4C530000 + slot`;
- имя: `vm_01.lua..vm_32.lua`;
- размещение: общий зарезервированный пул блоков `128..159`;
- максимальный размер текста UTF-8: 3968 байт.

Обычная кнопка `Записать` продолжает использовать HTTP API.

## Автоматическое чтение размещения OBJ1

Кнопка `Прочитать каталог` последовательно читает запись каталога и
128-байтный заголовок каждого объекта. Qt показывает Object ID, диапазон и
число блоков, фактический адрес payload в QSPI, назначение, имя и размер.
При выборе объекта автоматически заполняются его тип, ID, имя, link address,
API version, entry offset и флаги. Номер блока назначает allocator
контроллера; вручную задавать его не требуется.

## Папка модулей

Все готовые OBJ1-модули находятся в `D:\picoC\4\modules`. После сборки
туда автоматически записываются `profiler.bin` и `lua_vm.bin`. Кнопка
`Открыть` во вкладке OBJ1 сразу открывает эту папку. По имени файла Qt
автоматически выбирает тип, Object ID, API version и XIP link address.
