# Запись модуля во внешнюю W25Q128 через J-Link

`program_external_flash.jlink` записывает
`Release\Exe\module_slot0.bin` в слот 0 W25Q128.

Простая команда `loadfile` по адресу `0x90000000` не используется: это окно
QUADSPI предназначено для XIP-чтения. J-Link сначала помещает блок в служебное
RAM-окно `0x2407D000`, затем основной поток прошивки проверяет CRC, временно
останавливает операции FlashDB и вызывает `module_load_slot_buf()`.

## Первый запуск

Сначала один раз записать новую внутреннюю прошивку:

```powershell
& "C:\Program Files\SEGGER\JLink\JLink.exe" -CommanderScript "D:\picoC\2\program_internal_flash.jlink"
```

Подождать загрузку контроллера, затем записать внешний модуль:

```powershell
& "C:\Program Files\SEGGER\JLink\JLink.exe" -CommanderScript "D:\picoC\2\program_external_flash.jlink"
```

В начале внешнего скрипта намеренно нет `reset`: перед передачей блока основная
прошивка должна быть уже запущена и поток `mod_upload` должен работать.

## Результат в окне управления

J-Link выводит четыре 32-битных слова начиная с `0x2407E000`.

- `0x2407E000 = 0x454E4F44` — операция закончена (`DONE`);
- старшие 16 бит слова `0x2407E008` — состояние: `4` означает запись успешна;
- младшие 16 бит слова `0x2407E00C` — результат: `0` означает ошибки нет;
- старшие 16 бит слова `0x2407E00C` — вычисленный CRC16.

Для текущего `module_slot0.bin` ожидается CRC `0x3CA4`. Первое слово слота
`0x90000000` после записи должно быть `0x000C3CA4`.

## Запуск записанного модуля

Скрипт J-Link только записывает и проверяет слот. Поток модуля запускается
основной прошивкой функцией:

```c
#include "modules/qspi_modules.h"

int result = module_start_slot(0U);
if (result != MODULE_OK)
{
    LOG_E("Module slot 0 start failed: %d", result);
}
```

Вызывать `module_start_slot()` нужно только после успешного `fal_init()`.
Для демонстрационного модуля UART7 правильное место — конец
`storage_init_thread()` после инициализации Holding и архива:

```c
static void storage_init_thread(void *parameter)
{
    int result;

    (void)parameter;
    if (fal_init() > 0)
    {
        if (holding_flashdb_start() != RT_EOK)
            LOG_E("FlashDB holding start failed");
        if (arx_example_init() != RT_EOK)
            LOG_E("FlashDB archive start failed");

        result = module_start_slot(0U);
        if (result != MODULE_OK)
            LOG_E("Module slot 0 start failed: %d", result);
    }
    else
    {
        LOG_E("W25Q128/FAL initialization failed");
    }
}
```

`module_start_slot(0)` повторно проверяет заголовок и CRC, инвалидирует I-cache,
создаёт отдельный поток RT-Thread и вызывает точку входа
`0x90000000 + header.addr`. Для текущего модуля это `0x9000000C`.

## Дистанционный пуск и стоп через Modbus 06/16

Modbus function 05 и coils не используются. Управление выполняется через
существующее Holding-окно модулей:

| Holding | Назначение |
|---:|---|
| `12048` | номер слота `0..19` |
| `12050` | команда |

Команды для регистра `12050`:

| Значение | Действие |
|---:|---|
| `0xA503` | запустить выбранный слот |
| `0xA504` | остановить выбранный слот |

Последовательность запуска слота 0 двумя запросами function 06:

1. Записать `0` в Holding `12048`.
2. Записать `0xA503` в Holding `12050`.

Те же два регистра можно передать одним запросом function 16, если записать
диапазон `12048..12050`; значение промежуточного регистра `12049` в этом случае
задаётся `0`.

Команда ставится в очередь отдельного потока и ответ Modbus возвращается сразу.
Окончательный результат читается function 04:

Результат читается Modbus function `04`, начиная с адреса `2450`.
Function `03` по тем же адресам читает Flash Holding и не показывает TIT.

| TIT | Результат |
|---:|---|
| `2450` | состояние операции |
| `2451` | код `MODULE_*`; `0` — успешно |
| `2452` | CRC16 при проверке/записи модуля; для пуска/стопа не используется |
| `2453` | номер выбранного слота `0..19` |
| `2454` | длина загруженного блока; для пуска/стопа не используется |

Пример чтения трёх слов `TIT[2450..2452]` для ELAM-адреса 301:

```text
Запрос: F8 35 04 09 92 00 03 74 DA
Ответ: F8 35 04 00 06 00 07 00 00 00 00 DE 68
```

В приведённом ответе `TIT[2450]=7`, `TIT[2451]=0`,
`TIT[2452]=0`: модуль запущен без ошибки.

Состояния `TIT[2450]` для пуска/останова:

| Значение | Состояние |
|---:|---|
| `6` | запускается |
| `7` | запущен |
| `8` | останавливается |
| `9` | остановлен |
| `5` | ошибка, код находится в `TIT[2451]` |

Отрицательные коды `MODULE_ERR_*` отображаются в `TIT[2451]` как `u16`.
Например, `MODULE_ERR_BUSY = -9` читается как `0xFFF7`.

Повторный вызов для уже работающего слота вернёт `MODULE_ERR_BUSY`. Перед
повторным запуском или обновлением используется:

```c
module_stop_slot(0U);
module_start_slot(0U);
```

## Включение опроса демонстрационного модуля

После запуска поток существует, но опрос UART7 выключен, пока `TIT[2500]`
равен нулю. Параметр задаётся внутренней программой либо Modbus 06/16.
Рекомендуемая начальная настройка:

```c
TIT[2500] = 1U;     /* Включить опрос. */
TIT[2501] = 1000U;  /* Период опроса, мс. */
TIT[2502] = 1000U;  /* Масштаб 1.000. */
TIT[2503] = 0U;     /* Первое слово Modbus — старшая часть float. */
TIT[2504] = 0U;     /* Архивирование выключено; 1 = включено. */
```

Параметры `TIT[2500..2504]` разрешено задавать извне функциями Modbus 06/16.
Например, включение опроса:

```text
FC06: register 2500 = 1
```

Настройка всего блока одним запросом:

```text
FC16: start 2500, count 5
values: 1, 1000, 1000, 0, 0
```

Запись `2500..2504` изменяет именно внутреннюю таблицу TIT, а не Flash Holding.
Считывать параметры обратно нужно функцией 04. Все остальные адреса TIT через
функции 06/16 остаются защищёнными от записи.

Результат опроса виден через Modbus function 04:

- `TIT[2510]`, `TIT[2511]` — IEEE-754 float двумя словами;
- `TIT[2512]` — результат последнего обмена UART7;
- `TIT[2513]` — число успешных опросов.
