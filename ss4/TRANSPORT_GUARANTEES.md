# Гарантии транспорта (ss4)

Дата: 2026-03-05
Проект: `C:\andr\my2\ss4`

## Область
Документ задает runtime-гарантии обработки UDP request/response и concurrency планировщика, связанные с риском принятия неверного ответа (R3).

## Гарантированные инварианты
1. Ключ корреляции для маршрутизации UDP-ответа: `(ip, port, packet_id, dsr)`.
2. Ответ доставляется запросившей стороне только если есть соответствующая pending-запись.
3. При timeout pending-запись удаляется; поздние пакеты для этого запроса отбрасываются.
4. Для full-header frames проверяется ожидаемый `modem`; ответы с несовпадающим modem отбрасываются.
5. Для совместимости принимается раскладка заголовка ответа с переставленными `DSR/MODEM`.
6. Планировщик не запускает больше одной worker job одновременно для одного `kpz_id`.
7. Внутри одного glued Modbus execution chunk sends выполняются последовательно (`await` в цикле), а не параллельно.

## Операционный смысл
- Поздние UDP-пакеты не могут оживить timed-out request, потому что pending state уже удален.
- Cross-KPZ interference ограничен уникальной endpoint/modem адресацией и per-request correlation.
- Параллелизм разрешен между разными КПЗ, но не внутри одного КПЗ одновременно.

## Остаточные риски
1. Экстремальные сетевые условия — сильная переупорядоченность, дублирование, потери — все еще могут снижать свежесть/доступность данных.
2. Циклическое повторное использование идентификаторов (`packet_id`, `dsr`) имеет низкую, но ненулевую теоретическую вероятность коллизии на длинных runtime.
3. Short/legacy responses дают меньшую глубину проверки заголовка по сравнению с full-header frames.

## Обязательная stress-валидация
1. Доставка пакетов в переупорядоченном порядке.
2. Поздний пакет после timeout.
3. Дублирующиеся ответы.
4. Серии потерь пакетов.
5. Смешанные ответы с неверным/верным modem.

## Рекомендуемые метрики
1. `udp_rx_total`
2. `udp_rx_accepted`
3. `udp_rx_mismatch`
4. `udp_rx_late_drop`
5. `udp_timeout_total`
