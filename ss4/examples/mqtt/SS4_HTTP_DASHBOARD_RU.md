# HTTP-панель мониторинга `ss4`

Файл flow: `examples/mqtt/node_red_http_dashboard_flow.json`

Адрес панели после импорта в Node-RED:

```text
http://127.0.0.1:1880/ss4
```

Панель предназначена только для мониторинга. Управления, записи команд в оборудование и изменения уставок здесь нет.

## Схема

```text
ss4 -> MQTT broker -> Node-RED -> WebSocket -> /ss4
```

`ss4` публикует MQTT-сообщения. Node-RED принимает их через `mqtt in`, хранит последний snapshot в памяти flow, отдает его через `/ss4api`, пересылает live-сообщения в браузер через WebSocket `/ss4ws`, а страница `/ss4` обновляет таблицы без перезагрузки.

## MQTT topics

- `ss4/v1/status` - строка `online` / `offline`.
- `ss4/v1/health` - JSON с `kind` и `message`.
- `ss4/v1/values/{kpz_id}` - batch последних значений.
- `ss4/v1/alarms/{kpz_id}/{rule_id}` - событие аварии.

## Блоки панели

### Сводный индикатор

В верхней части панели есть общий индикатор состояния:

- `OK` - данные приходят, плохих качеств, устаревших значений и аварий нет;
- `NO DATA` - страница еще не получила MQTT-сообщений;
- `NO LIVE` - сообщения давно не приходили;
- `BAD` - есть значения с `quality` не `ok`;
- `STALE` - есть значения, которые не обновлялись дольше выбранного порога `stale`;
- `ALARMS` - есть активные аварии, то есть последнее состояние по правилу не `off/ok/clear`.

В той же строке показываются счетчики `values`, `filtered`, `visible`, `bad`, `stale`, `alarms` и возраст последнего сообщения. Для аварий формат `active/total`: активные состояния и всего известных состояний.

### Верхняя строка

- `filter` - фильтрация таблицы значений по `kpz`, `kpz_name`, `group_id`, `reg_id`, `addr`, `name`, `value`, `quality`.
- `all / bad / stale` - быстрый режим просмотра: все значения, только плохое качество, только устаревшие значения.
- `limit` - ограничение вывода таблицы: `100`, `500`, `1000`, `5000` строк.
- `stale 30s / 60s / 120s / 300s` - порог, после которого значение считается устаревшим.
- `clear filter` - очищает фильтр.
- `reset view` - сбрасывает фильтр, режим, лимит строк и сортировку к значениям по умолчанию.
- `refresh snapshot` - вручную подтягивает последний snapshot из Node-RED через `/ss4api`.
- `pause` / `resume (N)` - ставит live-обновление на паузу. Во время паузы сообщения буферизуются в браузере, число `N` показывает размер буфера, а накопленные сообщения применяются при `resume`.
- `clear alarms` - очищает аварии только на экране.
- `export values` - сохраняет видимые строки `Latest values` в CSV.
- `export alarms` - сохраняет текущую таблицу `Alarms` в CSV.
- `ws connected` - состояние WebSocket-соединения страницы с Node-RED.

### Карточки

- `status` - последнее состояние `ss4`.
- `health` - последнее health-сообщение scheduler.
- `visible / filtered / total` - сколько строк сейчас показано, сколько прошло фильтр и сколько всего значений хранится на странице.
- `stale` - сколько значений не обновлялись дольше выбранного порога `stale`.
- `bad quality` - сколько значений имеют `quality` не `ok`.
- `active alarms` - сколько аварий сейчас активно.
- `alarm states` - сколько уникальных состояний аварий хранится на экране по ключу `kpz/reg/rule`.
- `msg/min` - сколько MQTT-сообщений пришло за последнюю минуту.
- `last msg` - сколько секунд назад пришло последнее MQTT-сообщение.
- `snapshot` - время последней загрузки `/ss4api` и сколько `values/alarm states` пришло в snapshot.

### KPZ / group summary

Сводка группирует значения по `kpz_id/group_id` и показывает:

- `kpz` и `kpz name`;
- `group`;
- `total` - всего параметров в группе;
- `bad` - параметры с плохим качеством;
- `stale` - устаревшие параметры.

Строка сводки кликабельна: при клике фильтр автоматически устанавливается на выбранные `kpz/group`.

### Selected value

Показывает выбранный параметр из таблицы `Latest values`:

- `kpz`, `kpz name`, `group`, `reg`, `addr`, `name`;
- текущее `value`, `quality`, возраст значения;
- мини-график последних 120 числовых значений, накопленных в памяти браузера;
- `min`, `max`, `avg`, `samples` по текущему мини-графику;
- `clear trend` - очищает мини-график выбранного параметра.

История мини-графика хранится только в текущей вкладке браузера. После перезагрузки страницы она начинается заново.

### Таблица Latest values

Показывает последние значения по ключу `kpz_id/reg_id`.

Колонки:

- `kpz` - ID КПЗ.
- `kpz name` - имя КПЗ.
- `group` - группа регистра.
- `reg` - ID регистра.
- `addr` - адрес регистра.
- `name` - имя регистра.
- `value` - значение, округленное до 3 знаков.
- `quality` - качество значения.
- `age` - возраст значения в секундах.
- `received` - локальное время получения сообщения страницей.

Заголовки таблицы кликабельны: по ним можно сортировать значения.

Подсветка:

- красная строка - `quality` не `ok`;
- оранжевая строка - значение устарело, то есть не обновлялось дольше выбранного порога `stale`.

### Таблица Alarm states

Показывает агрегированные состояния аварий по ключу `kpz/reg/rule`, а не бесконечную ленту одинаковых событий. Если один и тот же сигнал часто переключается `on/off/on`, он остается одной строкой, а счетчик `repeats` растет.

Колонки:

- `last` - локальное время последнего события по этому ключу;
- `first` - когда первый раз увидели это состояние в текущей памяти Node-RED/страницы;
- `kpz` - ID КПЗ;
- `reg` - ID регистра;
- `rule` - ID правила;
- `state` - последнее состояние события;
- `value` - значение на момент события;
- `sev` - severity;
- `repeats` - сколько событий по этому ключу было схлопнуто в одну строку;
- `code` - код;
- `message` - текст.

Активные состояния подсвечиваются красным. Строка аварии кликабельна: при клике панель ставит фильтр по `kpz/reg` и выбирает соответствующий параметр в блоке `Selected value`, если это значение уже есть на странице.

## Ограничения

- Долгая история не хранится в этой панели. Для истории лучше использовать существующую БД `ss4` или отдельный контур `MQTT -> Telegraf -> InfluxDB/Grafana`.
- CSV-экспорт выгружает только то, что сейчас есть в памяти страницы: видимые значения после фильтра и текущие агрегированные состояния аварий.
- Панель не делает управление. Это осознанно: мониторинг безопаснее держать отдельно от команд записи.
- WebSocket работает локально через Node-RED. Если Node-RED остановлен, страница не будет получать обновления.
- При перезагрузке страницы, при переподключении WebSocket и по кнопке `refresh snapshot` `/ss4` подтягивает последний snapshot из Node-RED через `/ss4api`. Это не долгая история, а только последние значения и агрегированные состояния аварий, которые Node-RED уже видел.
- При 10000 параметров используйте фильтр, быстрые режимы и лимит строк. Таблица не должна постоянно отрисовывать все строки, если оператор смотрит только проблемные.
- Live-отрисовка MQTT-сообщений сглажена: частые входящие пакеты схлопываются в обновления экрана примерно раз в 250 мс, чтобы не перегружать браузер.
- Настройки просмотра сохраняются в `localStorage` браузера: `filter`, режим `all/bad/stale`, лимит строк, порог `stale` и сортировка восстанавливаются после перезагрузки страницы. Для возврата к настройкам по умолчанию используйте `reset view`.

## Быстрый порядок запуска

1. Запустить Mosquitto на `127.0.0.1:1883`.
2. Запустить `ss4` с включенным `[mqtt]`.
3. Запустить Node-RED.
4. Импортировать `examples/mqtt/node_red_http_dashboard_flow.json`.
5. Открыть:

```text
http://127.0.0.1:1880/ss4
```
