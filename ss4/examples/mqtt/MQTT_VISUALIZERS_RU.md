# MQTT-визуализаторы для `ss4`

## Короткий выбор

```text
Быстрая проверка MQTT       -> MQTTX
Локальный операторский экран -> Node-RED + /ss4
Красивый dashboard          -> FlowFuse Dashboard
Live-графики                -> Grafana MQTT datasource
История и тренды            -> Grafana + InfluxDB/TimescaleDB
Большая IoT-платформа       -> ThingsBoard / EMQX
```

## 1. MQTTX

Назначение: проверка broker, topics и payload.

Плюсы:

- быстро подключается к `127.0.0.1:1883`;
- удобно смотреть `ss4/v1/#`;
- видно raw JSON;
- хорошо подходит для диагностики.

Минусы:

- нет нормального операторского экрана;
- нет графиков процесса;
- нет истории.

Рекомендация для `ss4`: оставить как инструмент наладки.

## 2. Node-RED + `/ss4`

Назначение: локальный операторский экран и первичный мониторинг.

Текущий flow:

```text
examples/mqtt/node_red_http_dashboard_flow.json
```

Адрес:

```text
http://127.0.0.1:1880/ss4
```

Плюсы:

- работает без дополнительных dashboard-пакетов;
- показывает `status`, `health`, `values`, `alarms`;
- есть фильтр, pause/resume, clear alarms;
- есть `msg/min`, `last msg`, `stale`, `bad quality`;
- легко дорабатывать под формат `ss4`.

Минусы:

- история не хранится;
- при очень большом числе параметров нужна фильтрация/виртуализация строк;
- дизайн простой.

Рекомендация для `ss4`: основной текущий вариант.

## 3. FlowFuse Dashboard / Node-RED Dashboard 2.0

Назначение: более красивый dashboard в Node-RED.

Плюсы:

- современнее старого `node-red-dashboard`;
- есть UI widgets;
- удобно делать карточки, таблицы, графики;
- хорошо ложится на Node-RED.

Минусы:

- нужен отдельный npm-пакет;
- потребуется собрать flow под Dashboard 2.0;
- для 10 000 параметров все равно нужны фильтры.

Рекомендация для `ss4`: следующий шаг, если нужен более красивый операторский экран.

Установка:

```powershell
cd $env:USERPROFILE\.node-red
npm install @flowfuse/node-red-dashboard
```

## 4. Grafana MQTT datasource

Назначение: live-графики напрямую из MQTT.

Плюсы:

- Grafana умеет красивые панели;
- есть MQTT datasource plugin;
- можно быстро строить live-графики по topics.

Минусы:

- MQTT datasource больше про live, а не надежную историю;
- payload `values/{kpz_id}` нужно преобразовывать в удобные series;
- для больших batch JSON может понадобиться промежуточная обработка.

Рекомендация для `ss4`: использовать для live-графиков после нормализации данных.

Официальный plugin:

```text
https://grafana.com/grafana/plugins/grafana-mqtt-datasource/
```

## 5. Grafana + InfluxDB/TimescaleDB

Назначение: история, тренды, отчеты.

Схема:

```text
ss4 -> MQTT -> Telegraf/Node-RED -> InfluxDB/TimescaleDB -> Grafana
```

Плюсы:

- нормальная история;
- быстрые тренды;
- выбор периодов;
- агрегации;
- удобно смотреть большие объемы.

Минусы:

- больше компонентов;
- нужна схема хранения;
- нужно продумать retention policy.

Рекомендация для `ss4`: лучший вариант для истории и графиков за период.

## 6. ThingsBoard / EMQX / другие IoT-платформы

Назначение: большая IoT-система с устройствами, пользователями, правами, rules.

Плюсы:

- много готовых IoT-функций;
- пользователи и роли;
- alarm/rule engine;
- dashboards.

Минусы:

- тяжелее;
- больше настройки;
- может быть избыточно для локального `ss4`.

Рекомендация для `ss4`: рассматривать позже, если нужен многопользовательский web-контур.

## Итоговая рекомендация

Для текущего этапа:

```text
MQTTX                  -> диагностика
Node-RED /ss4          -> основной live-мониторинг
Grafana + storage      -> история и тренды позже
FlowFuse Dashboard     -> если нужен красивый операторский UI
```

Для 10 000 параметров:

- не выводить все строки сразу;
- использовать фильтр;
- показывать сводки;
- группировать по `kpz_id` / `group_id`;
- для истории использовать БД, а не браузерную таблицу.
