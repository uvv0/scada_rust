# Пространства ключей `rv(...)` в SS4

Этот документ описывает допустимые пространства ключей для `rv(...)` в скриптах `ss4`.

## 1. Ключи `reg_id` — прямой доступ

- Диапазон: положительные ID регистров из таблицы `reg.id`.
- Смысл: последнее runtime-значение конкретного регистра.
- Источник в коде: `SchedulerState::set_rv(..., r.id as i64, ...)`.

## 2. Ключи-адреса — fallback по адресу

- Диапазон: Modbus «человеческие» адреса, обычно `30001..49999`.
- Смысл: значение ищется через `reg_id_by_addr`, затем берется значение регистра.
- Назначение: поддержка legacy-скриптов, которые вызывают `rv(30401)` как адрес.

## 3. Сервисные ключи — область одного КПЗ

- База: `svc_base_for(kpz_id) = 1_000_000_000 + kpz_id * 200_000`.
- Формула: `svc_key(kpz_id, offset) = base + offset`.
- Примеры `offset`:
  - `60000 + slot*2` — флаг готовности индекса.
  - `60000 + slot*2 + 1` — стабилизированное значение.
  - `80000 + slot` — качество индекса.

## 4. Scoped ARX индекс-ключи

- Формула: `svc_arx_key(kpz_id, arx_id) = base + 40000 + arx_id`.
- Смысл: зеркальное runtime-значение `arx_state.last_ind` для конкретного архива.

## 5. Alias-ключи для скриптов (`71000 + arx_id`)

- Ключ в скрипте: `71000 + arx_id`.
- Поведение runtime: ключ remap-ится в scoped ARX key (`base + 40000 + arx_id`).
- Важно: для этого alias запрещен fallback на адресное пространство.

## 6. Legacy fallback-ключ

- Формула: `-2_000_000_000 + key`.
- Статус: путь обратной совместимости, планируется отключение.
- Управление: `SchedulerState::ENABLE_LEGACY_RV_FALLBACK`.

## Порядок разрешения в `get_rv`

1. Scoped ARX direct range (`base+40000 .. base+109999`).
2. Alias ARX range (`71000..79999`) -> scoped key.
3. Прямой поиск по ключу.
4. Поиск как адрес (`addr -> reg_id`).
5. Legacy fallback (`-2_000_000_000 + key`), если включен.
6. По умолчанию `0.0`.

## Источник в debug-логах

`get_rv` пишет поле `source` со значениями:

- `scoped`
- `scoped-miss`
- `direct`
- `address`
- `legacy`
- `miss`
